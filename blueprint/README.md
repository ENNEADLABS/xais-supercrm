# Blueprint historique

Ces documents retracent les intentions produit et les arbitrages étudiés avant et
pendant la construction du prototype. Ils sont utiles pour comprendre la démarche,
mais ne décrivent pas toujours l'implémentation actuelle.

Pour travailler sur le code, utilise dans cet ordre :

1. le [`README`](../README.md) pour le démarrage et le statut du projet ;
2. [`docs/layout.md`](../docs/layout.md) pour la structure actuelle ;
3. les [`docs/decisions/`](../docs/decisions/) pour les décisions durables ;
4. le code et les tests comme arbitres finaux du comportement.

Les contradictions résiduelles dans les analyses historiques doivent être lues comme
des options envisagées, pas comme des exigences.
